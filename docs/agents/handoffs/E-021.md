3. **Decisions made**
   - Followed Notion 11 §3.1/3.2 key names and templates verbatim; added the three keys above so today's access
     maps 1:1. `x.all` implies `x.own`.
   - Several memberships per person per academy are allowed (grants add up) — e.g. advisor for all leads +
     instructor for one cohort. Scope = courses / cohorts / `ownRecordsOnly`; a scope that needs a field the
     collection lacks denies (never widens). Cohort-only scope on lessons denies; course scope covers them.
   - Legacy `users.roles` kept only for the `super-admin` platform flag and `student`; it no longer grants staff
     access. Removing the field is a later cleanup.
   - Status values per the task: active / suspended / archived (Notion's invited/expired come with the invite flow).
   - No escalation also covers editing people: you cannot edit (password, email, status) an account whose access you
     could not grant yourself; platform admins are untouchable from inside an academy.
   - Last role manager rule applies to everyone, platform admins included; the very first manager of an academy is
     allowed (bootstrap).
   - Audit rows are written in the same transaction: if the audit write fails, the change fails (accountability over
     availability). Secrets/password/merchant ID/national code are redacted in the diff.
   - TOTP verified per session (`sid`), enforcement for un-enrolled staff behind `STAFF_2FA_REQUIRED` (default off)
     — see ADR 007. Nothing reverses ADR 006.
   - Field-level money rules: `price`/`maxInstalments`/`priceOverride` need `pricing.edit`; publishing needs
     `courses.publish`; testimonial approval / post publish date need `content.publish`; revoking a certificate needs
     `certificates.revoke`; reassigning a lead needs `leads.assign`.
