3. **Decisions made**
   - **Walked, not read.** Every flow was driven in the app on a fresh DB (`SEED_TENANTS=demo`, mock SMS and payment) with Playwright scripts, as the academy-admin, advisor, finance, support and instructor templates and two students. Each label in the guides is copied from the captured screen text, and the claims about behaviour were checked in code. Things done for real: lead form → assign → advisor call log; settings save; course, lesson and cohort created; image uploaded in the editor; quiz failed, then passed; assignment submitted and graded; certificate refused and then issued; custom role and scoped membership; user created; 2FA enrolled, verified, disabled and reset.
   - **Structure from the ux-architect review:** role first, first-hour order, manager's "people and roles" moved to page 3 (advisors see nothing until leads are assigned), one `coming-soon.md` instead of per-role placeholder pages, a shared `troubleshooting.md`.
   - **The admin's English labels are quoted as they appear,** with the Persian meaning in brackets and in the glossary. Translating them in the text would send users looking for words that aren't on screen.
   - **product-manager accuracy review applied:**
     - Extra quiz attempts are manager-only (`enrollments.manage`), not instructor.
     - The grading permission is `submissions.grade`.
     - The staff lock message is the E-034 one.
     - OTP codes last 2 minutes.
     - A required quiz gates the next lesson only under the "after previous" drip rule.
     - Unbuilt template abilities are no longer listed as role jobs.
     - Advisors have no orders access.
     - The WordPress and gamification «next release» lines are taken from the PR #19 and #21 descriptions (QA GO on both). Recheck them when each PR merges.
   - **Latin HTML anchors** (`<a id="drip">`) for every in-page link. GitHub's heading slugs for Persian text with half-spaces and «؟» are unreliable.
   - **Persian cleanup:** `persian_cleanup.py --edit` ran through a small wrapper. The wrapper shields link targets, code, bold UI labels and «quoted UI copy», skips heading lines and drops the `fix_arabic_chars` step. Run unshielded, the script rewrote `../images/student-01…` to `./images/student-۰۱…`, and turned تأیید/سؤال into تایید/سوال, unlike the UI. Those spellings are in headings and anchors, so the change would have broken links. `fa_lint.py --check` reports 0 issues on all 29 files.
   - **Steps use «۱.» with a blank line between them** so GitHub renders one step per line. A Latin `1.` list would put Latin numerals on the wrong side in RTL.
   - **Screenshots:** the mock "dev mode" SMS code line is hidden. The 2FA QR and key are blurred, and the wrong-code screen is cropped to the error. No IBA data: the IBA tenant was not seeded.
   - **The README docs-map link was not added:** see open issue 1.
