# E-034 — Login pages with personality (Seal card, every state)

**Agent:** ux-architect → ui-designer → tech-lead → qa · **Date:** 2026-11-06 · **Branch:** feature/ui-e034-login-options

1. **Task:** Give the three logins (student SMS `/login`, staff `/staff/login` + 2FA, Payload `/admin/login`) real personality in the Seal direction, in several options, with every state. Farjad picked **Option B · Seal card** at the approval gate. UI only: auth, permissions and 2FA behaviour are unchanged.
2. **Output:**
   - Spec: `docs/ux/E-034-login.md`. It covers the entry points, about 60 states (each flagged exists / UI-only / BACKEND), the copy sheet, a11y and wireframes.
   - Options: `docs/design/e034/` has 3 options × 33 screens (desktop/mobile, light/dark, teal/wine), `contact-a/b/c.png`, `side-by-side.png` and a README. The dev preview route was removed after the pick.
   - Implementation:
     - `packages/ui/src/seal.tsx` (`@edvora/ui/seal`: seal mark, guilloche, star rule, icons).
     - `packages/core/src/login.ts` + test (`@edvora/core/login`, maps existing server responses to states).
     - `apps/web/src/components/auth/` (AuthFrame, kit, fields, StudentLoginForm) and `lib/authBrand.ts`.
     - Rewritten pages: `/login`, `/staff/login`, `/staff/2fa/verify`, `/staff/2fa/enrol`. Restyled staff forms.
     - `components/admin/LoginSkin.tsx` (Payload `graphics.Logo`, `beforeLogin`, `afterLogin`) and login-scoped `custom.scss`.
     - `PublicChrome` hides the site header/footer on `/login` and `/staff/*`.
   - Tests: `e2e/tests/login.spec.ts` + `login-helpers.ts`, 56 tests. They cover each wired state, axe wcag2a/aa in light and dark, 375px with no overflow, both tenants' colours, and keyboard order.
3. **Decisions made:**
   - **Option B · Seal card** (Farjad). It's the only option that holds up when a tenant has no logo, stats or tagline, and it matches the E-027 certificate seal.
   - **One family, separate doors:** the student login stays separate. `/staff/login` is the recommended single staff+admin door. `/admin/login` is skinned and links to it, but does **not** redirect yet (needs approval, see open issue 1).
   - Welcome line = tenant `tagline`, falling back to the tenant name. No new field was added.
   - Locked admin/staff account: Payload returns 401 `LockedAuth` with no `lockUntil`. We map it to the "locked" banner **without** a countdown. This was checked in `payload/dist/auth/operations/login.js` 3.93.
   - `beforeLogin` runs after the password check, so the suspended/archived message does not reveal whether an account exists.
   - No gold on login: gold is reserved for milestones.
