3. **Decisions made:**
   - New key `leads.claim` instead of widening `leads.view.own` — `.own` drives the REST read/update filter; widening it
     would expose unassigned leads through `/api/leads` (ADR 022).
   - ownRecordsOnly ⇒ no pool, whatever the roles hold. Course-scoped pool fails closed for leads without a course.
   - Claim is a conditional update (`advisor exists: false`), so two advisors cannot both win.
   - Timeline reads status/owner history from the audit log (`leads.update` diffs) — no new history table. Calls come
     from `followUps`; orders are matched by the lead's mobile → user in this academy.
   - Audit = the existing `auditChange('leads')` row per write (actor + diff); no second, duplicate row.
   - «Convert» = link to the public course page (the existing checkout); «ساختن سفارش در پنل مدیریت» for holders of
     `orders.create_for_lead`. No staff-side checkout was built.
   - Mark lost without a call logs a `status_changed` follow-up (counts as handled for the daily goal, PRD §4.1) and
     keeps the stage default revisit in 30 days.
   - "Conversion this month" = of leads created this Jalali month, the share now enrolled (cohort view, from data we
     have; there is no `enrolledAt` on leads).
   - Date filter is presets (today / 7 days / this month / all) rather than a free date range.
