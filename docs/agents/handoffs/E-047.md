# E-047 — Settings hub («تنظیمات»)

**Agent:** tech-lead (Claude session) · **Date:** 2026-11-08 · **Branch:** feature/settings-hub

1. **Task:** one central Settings section in the admin where everything configurable lives (Farjad: "from logo upload,
   colours and titles to APIs and the rest"), with hook points for E-045 payments and E-046 AI.
2. **Output:**
   - ADR [019](../../adr/019-settings-hub.md); screenshots in `docs/adr/E-047/`.
   - `/admin/settings[/section]` (Payload custom view, Seal console look): identity (name, tagline, logo light/dark,
     favicon, OG), appearance (colours with live preview + AA checks, theme, self-hosted display font), contact &
     social, SEO, homepage blocks, certificates (prefix, signer, signature), message templates (SMS/email per event
     with variables), login texts, site toggles + gamification, legal pages, integrations (SMS/Kavenegar, SMTP,
     BigBlueButton; sealed write-only keys, test connection), platform (providers status, academy-provider switch,
     staff 2FA policy, per-academy domains/plan/limits/modules).
   - Section registry `apps/web/src/lib/settingsRegistry.ts`: Payments (`payment-methods`, `payments.settings`) and
     AI (`ai-settings`, `ai.manage`) link entries appear once their collection exists; roles, memberships, audit
     log and import are listed too.
   - Public site uses the settings (header logos, favicon/OG/SEO metadata, font, footer social + legal, toggles,
     login texts); SMS uses the academy's own Kavenegar account when on.
   - Core rules + Vitest (`settings.test.ts`, `settingsSecrets.test.ts`), connection checks + tests
     (`packages/integrations/src/connection`), colour checks (`@edvora/ui/color`), e2e `settings-hub.spec.ts`.
   - Migrations: `e047_settings_hub` (schema), `e047_admin_integrations_key` (academy-admin roles get the new key),
     `e047_zarinpal_to_payment_methods` (old merchant id → disabled, sealed Zarinpal row in payment-methods).
3. **Decisions made:**
   - Hub in Payload `/admin` (as asked), styled with `ed-set*` SCSS on console tokens — Payload admin has no Tailwind
     (same as roles-compare, ADR 016).
   - Plain HTML forms → route handler with 303 (ADR 005), same-origin check; no server actions.
   - New permission `settings.integrations`, separate from `settings.edit` (keys spend money and send in the
     academy's name).
   - Keys sealed per academy+kind (`SETTINGS_SECRETS_KEY`, else `PAYLOAD_SECRET`); field `hidden`, collection
     closed to API writes; audit logs `[changed]` / `[removed]` only.
   - SSRF guard on staff-typed hosts (SMTP/BBB) in production.
   - Colours that fail AA are refused with the nearest passing shade offered.
   - `/verify` toggle only hides the menu link (printed certificates' QR codes must keep working).

   - Academy BBB and SMTP are stored and tested, not used at runtime yet (BBB webhooks/recordings use the instance

   - GraphQL `/api/graphql` returns 500 on develop already (`Questions.ts` select value `'true'` is not a valid

   - Locally, `gamification.spec.ts` 1b (real video playback) timed out on `video.play()`; unrelated to these files.
