**Task** · A visitor on `/demo` gets an isolated sandbox academy (staff + student) valid for `SANDBOX_TTL_HOURS` (3 h), then it expires and is purged.

**Output**
- Spec: `docs/product/sandbox-demo.md` (PM). ADR: `docs/adr/013-sandbox-tenants.md`.
- Core: `packages/core/src/{sandbox,pow,sandboxSecurity}.ts` + Vitest. Web: `lib/sandbox/*`, `access/sandbox.ts`, `/demo/*` routes, countdown banner (one element in `/staff`, `/dashboard`, `/learn` layouts).

**Decisions made**
- Routing: signed `edvora_sbx` cookie on the platform host only (no wildcard DNS on `*.up.railway.app`); 303 route handlers, no server-action `redirect()` (ADR 005).
- Tenant-level `isSandbox`/`expiresAt`/`purgeAt`; memberships clamped. `/admin` closed to sandbox users (403); staff work in `/staff`.
- Student login: generated username + password (no phone/OTP inside a sandbox).
- Forced mock for every outbound path in sandboxes: payments (all E-045 gateways, Tether verifier), SMS, live classes, AI (E-046); WordPress import refused. Secrets (gateway creds, card numbers, wallets, AI keys) cannot be written (403).
- Cleanup cron `/demo/api/cleanup` (Bearer `SANDBOX_CRON_SECRET`) hard-deletes only `isSandbox` tenants after grace — the one hard-delete exception (ADR 013). Refuses to run if a tenant-owned collection is missing from the purge list.
- Defaults pending Farjad: TTL 3 h fixed, max 20 active, 3/IP/day + 1 live per IP, grace 24 h, `SANDBOX_ENABLED` off by default.
