**Decisions made**
- Routing: signed `edvora_sbx` cookie on the platform host only (no wildcard DNS on `*.up.railway.app`); 303 route handlers, no server-action `redirect()` (ADR 005).
- Tenant-level `isSandbox`/`expiresAt`/`purgeAt`; memberships clamped. `/admin` closed to sandbox users (403); staff work in `/staff`.
- Student login: generated username + password (no phone/OTP inside a sandbox).
- Forced mock for every outbound path in sandboxes: payments (all E-045 gateways, Tether verifier), SMS (incl. E-047's academy SMS account via `getSmsFor`), live classes, AI (E-046); WordPress import refused. Secrets (gateway creds, card numbers, wallets, AI keys) cannot be written (403).
- E-047 settings hub: `integration-settings` (SMS, email, live) is mock-only in sandboxes — a real provider, any secret or any provider config is refused with 403 (hub route and collection hook, rule `sandboxIntegrationViolations` in core); «test connection» never connects; `academyProvider()` returns nothing for sandboxes, so any future email/live sender is forced too; platform sections stay platform-only; `/admin` (where the hub lives, ADR 019) stays closed to sandbox users; platform `limits` added to the locked tenant fields. Payments and AI hub entries link to the already-locked `payment-methods` (now holding the gateway merchant id) and `ai-settings`.
- Cleanup cron `/demo/api/cleanup` (Bearer `SANDBOX_CRON_SECRET`) hard-deletes only `isSandbox` tenants after grace — the one hard-delete exception (ADR 013). Refuses to run if a tenant-owned collection is missing from the purge list.
- Defaults pending Farjad: TTL 3 h fixed, max 20 active, 3/IP/day + 1 live per IP, grace 24 h, `SANDBOX_ENABLED` off by default.
