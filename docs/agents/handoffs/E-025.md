3. **Decisions made:**
   - Dockerfile over Railpack — monorepo + workspace TS packages + `sharp` build reliably and the same image is
     portable to an Iranian host later.
   - Seed **demo only**. The `iba` seed has no "Ministry of Science" claim (only a warning comment), but it does carry
     `TODO(client)` fees, real client logos/contact details and testimonials whose consent must be re-confirmed — not
     for a public URL.
   - Tenant resolution via `DEFAULT_TENANT_SLUG=demo` fallback; the Railway domain is not added to the demo tenant's
     `domains` (not needed, and keeps the seed host-agnostic).
   - Seed runs from a dev machine through a temporary TCP proxy with `NODE_ENV=production`, so Payload applies the
     committed migrations instead of dev schema push. Seeded before first deploy because the healthcheck needs a tenant.
   - No BuildKit cache mount in the Dockerfile — Railway rejects cache ids without its service-ID prefix.
4. **Open issues:**

     migrate`) or move settings to the dashboard before then.
   - Not tested from inside Iran — Railway may need a VPN there.
   - Media uploads live on container disk and vanish on redeploy (demo has none). Production needs object storage.
   - `next start` locally now prints a standalone-mode warning; dev and e2e (`next dev`) are unaffected.
   - Browser pane was hidden, so flows were verified with Playwright (headless Chromium, desktop) rather than
     screenshots; mobile/dark mode not re-checked on Railway.
