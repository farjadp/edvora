## Decisions made
- Package ships TS source (like `@edvora/core`) — no build step; Next transpiles it.
- `@import 'tailwindcss'` stays in the app; `@edvora/ui/styles.css` assumes Tailwind is already imported. This keeps
  one Tailwind instance and lets each app add its own `@source`.
- `CoverArt` takes plain props instead of a Payload `Course`, so `@edvora/ui` never depends on app types. The app's
  `CourseArt` adapter keeps every call site unchanged.
- `CourseCard` stays in the app for now (uses `next/link`, Payload types and `@edvora/core` formatting).
- Class helpers are string functions, not `<Button>`/`<Input>` components, so server-action forms keep native
  elements and `useActionState` wiring untouched.
- Only swapped call sites whose classes were **exactly** equal to a helper's output; buttons with different padding /
  no hover (e.g. `/verify` submit, `not-found`, `payments/result`) are left inline to keep "no visual change" strict.
- Reworded a code comment containing the word "container" — Tailwind scanned it and emitted an unused `.container`
  utility.
