# E-031 — Seal theme for Payload `/admin` + full rich-text editor with image upload

**Agents:** ui-designer → tech-lead → qa (orchestrated) · **Date:** 2026-11-06 · **Branch:** feature/admin-seal-editor

1. **Task:** Farjad asked "Why didn't the admin's look change?" (E-027/E-028 covered only the student panel and `/staff`)
   and asked for a professional rich-text editor, image upload included, wherever the admin needs long text.

2. **Output**
   - **Admin theme:** `apps/web/src/app/(payload)/custom.scss` (Payload theme variables with `--ed-*` Seal tokens,
     light + dark, RTL, editor surfaces), `apps/web/src/components/admin/{Brand,TenantAccent,DashboardHome}.tsx`,
     `apps/web/src/lib/adminTenant.ts`, `admin.components` in `payload.config.ts`. Self-hosted fonts: Vazirmatn and
     Space Grotesk (@fontsource), Morabba (existing `public/fonts/morabba`). Documented in `docs/design/system.md`.
   - **Dashboard landing:** greeting, up to 4 tenant-scoped counts (published courses, new leads, active enrolments,
     submissions awaiting grade) and quick links. Each is shown only if the user's Payload permissions allow it.
   - **Editor:** `apps/web/src/lib/richText.ts` (`richTextEditor`, `richTextField()`). It has H2–H4, bold, italic,
     underline, strikethrough, inline code, links (external + internal to courses/lessons), bullet/numbered/check
     lists, blockquote, hr, alignment, indent, tables (`EXPERIMENTAL_TableFeature`), and image upload into Media with
     required alt. There is a fixed toolbar and an inline toolbar.
   - **Tenant isolation:**
     - Server `tenantGuard` (`beforeChange`) rejects cross-tenant uploads, links and relationships.
     - The pickers are filtered to the selected academy.
     - The renderer only resolves same-tenant media and docs.
     - Helpers and tests: `packages/core/src/richtext.ts` (`@edvora/core/richtext`).
   - **Migration:** `apps/web/src/migrations/20261106_230318_e031_rich_text.ts`. It changes varchar → jsonb and
     converts text ↔ Lexical. It is safe on rows that are already Lexical and on columns that are already jsonb. A
     `beforeValidate` hook also turns plain strings sent by API importers into Lexical.
   - **Renderer:** `apps/web/src/components/RichText.tsx` (RTL prose, tables, checklists, Persian list numerals,
     `next/image` with alt). Used on home (manifesto), course page (syllabus, FAQ), `/learn` lesson notes, quiz
     description, attempt explanation, and assignment description/feedback.
   - **Tests:** `packages/core/src/richtext.test.ts` and the e2e test `e2e/tests/rich-text.spec.ts`.
     `@axe-core/playwright` is added as a dev dependency.
   - **Screenshots:** `docs/design/e031/before-*`, `after-*` (iba), `after-*-demo` (demo), `qa-*`. Capture script:
     `docs/design/e031/capture.mjs`.
   - **ADR:** `docs/adr/010-rich-text-lexical.md`.

3. **Decisions made**
   - **Converted to rich text:**
     - Courses `syllabus[].description` and `faq[].answer`
     - Tenants `manifesto`
     - Users `publicProfile.bio`
     - Lessons `notes`
     - Quizzes `description`
     - Assignments `description`
     - Questions `explanation`
     - Submissions `feedback`
     - Posts `body` was already rich text; it now uses the shared field and gets the tenant guard.
   - **Kept as textarea:**
     - Courses `summary` (used as the meta description)
     - Courses `audience[].text` and Tenants `services[].text` (card blurbs)
     - Questions `text` (snapshotted into attempts as a string)
     - Submissions `text` (the student types it in a plain form)
     - Leads `message` and activity `text`
     - Content `quote` and `excerpt`
     - Roles `description`
     - Users `internalNotes`
     - Course outcomes were already one-line `text` fields.
   - **Admin styling:** Tailwind is not loaded inside Payload admin, so the admin components use `ed-*` classes from
     `custom.scss`. This is a documented exception to "Tailwind only".
   - **Gold `--milestone`:** not used in admin. There are no milestones there.
   - **Accent colour:** comes from the academy selected in the admin. It falls back to Edvora blue when none is
     selected.
   - **Tables:** use Payload's experimental feature. It works in 3.93 and is noted in ADR 010.
   - **QA fixes:**
     - The Persian heading labels showed "[SKIPPED]"; patched.
     - The internal-link picker listed every academy's content; it is now scoped.
     - Contrast fixes.
     - The upload card was clipped at 375px; fixed.
   - Next.js `agentRules: false` stops `next dev` from writing `apps/web/AGENTS.md` and `apps/web/CLAUDE.md`.

4. **Open issues**
   - **Farjad decides:** accept the remaining axe findings as upstream Payload core, or schedule aria overrides? The
     findings are react-select labels, icon-only button names, the editor image alt, the contenteditable name and
     list roles. There are no colour-contrast violations left.
   - **Farjad decides:** should the home manifesto get a prose layout? It is styled as large centred type, so
     headings, lists and tables look odd there.
   - **Pickers:** they follow the selected-academy cookie, not the document's own academy. The server guard still
     rejects a wrong save, but the experience is confusing for a super admin.
   - **Bio images:** a user with no academy cannot add images or internal links to a bio.
   - **Down migration:** it keeps the text but drops formatting, images and links.
   - **Minor:**
     - The table dialog is untranslated (English).
     - The editor shows Latin digits in ordered lists; the public site shows Persian numerals.
     - FAQ JSON-LD can include alt text from a cross-tenant image, but only if one was planted directly in the DB.
   - **Merge order:** E-028 (Seal build) and E-030 (PR #17) also touch `payload.config.ts`, migrations and
     `payload-types.ts`. Whoever merges second re-creates their migration. The E-031 migration is self-contained:
     re-run `payload migrate:create` and paste in its body. E-030 may also have imported content into converted
     fields; the migration and the `beforeValidate` hook handle both text and Lexical.
   - **Shared files with E-028:** four `/learn` pages each got a one-line swap to `<RichText>`: lesson, quiz, attempt
     and assignment.
   - **Dashboard wording:** "Active enrolments" counts enrolment rows, not distinct students. Confirm the label.
   - **Dev mode:** a DB with a dev-mode `payload_migrations` row (batch -1) makes `payload migrate` hang on an
     interactive prompt.
   - **`.claude/worktrees/admin-visual`:** an uncommitted worktree (branch `feature/admin-visual`) that no known
     session owns. Left untouched. It contains:
     - an 818-line `custom.scss` re-theme
     - a tenant "Appearance" tab: DB fields, a migration, a colour field, live preview, per-tenant fonts and sizes
       (`packages/ui` `appearance.ts` and `fonts.ts`)
     - admin Brand, DashboardHeader and TenantAppearance components
     - a frontend layout change to `siteAppearanceCss`

     E-031 borrowed only its SCSS structure and the hairline nav and dashboard ideas.
