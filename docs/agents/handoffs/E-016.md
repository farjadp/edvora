# E-016 — SMS reminders worker

**Agent:** tech-lead (Claude session) · **Date:** 2026-11-09 · **Branch:** feature/notifications-sms-reminders

1. **Task:** automatic SMS reminders — instalments (before / on / after due), live classes (before start, enrolled
   students), advisor morning digest of due follow-ups; per-academy offsets and quiet hours; one send per reminder per
   recipient; opt-out; templates in the settings hub; scheduled idempotent worker; send log with retry; mock-only for
   `demo` and sandboxes; global kill switch.
2. **Output:**
   - Rules: `packages/core/src/reminders.ts` (+ 21 Vitest tests). New template events `instalment.overdue`,
     `followup.digest`; permissions `notifications.view`, `notifications.manage` (catalog, descriptions, templates).
   - Worker: `apps/web/src/lib/reminders/worker.ts`; route `POST /api/cron/reminders` (Bearer `REMINDERS_CRON_SECRET`,
     404 when unset; `SMS_REMINDERS_ENABLED` kill switch, default false).
   - Data: collection `sms-log` (tenant-owned, plugin + sandbox purge), `tenants.reminderSettings`, `users.smsReminders`.
     Migrations `20261109_140046_e016_sms_reminders` + `20261109_140100_e016_notifications_grant`.
   - Settings hub section «یادآورهای پیامکی» (`notifications.manage`); send log in the admin menu (`notifications.view`).
   - Seed: `demo` reminders on; IBA off.
   - Tests: `e2e/tests/sms-reminders.spec.ts` (404 without secret; quiet hours defer; due instalment → exactly one mock
     send; rerun no duplicate; log access by role; settings form), `access-matrix.spec.ts` rows. CI e2e env sets the
     three reminder vars (mock SMS only).
   - Docs: ADR 020, `docs/runbooks/sms-reminders.md`, `docs/guide/academy-admin/10-sms-reminders.md`, access matrix.
3. **Decisions made:**
   - Cron route, not the Payload jobs queue — `autoRun` runs in both `web` and `web-iba` (one DB); periodic scan fits a
     cron; same pattern as E-029 cleanup.
   - Log row with unique key inserted before the send → at most once; crash mid-send = `unknown`, never retried.
   - Instalment reminders only for `partially_paid` site orders (pending may be an abandoned checkout; imports never notify).
   - Reminders off per academy by default; kill switch off by default.
   - A missed day's instalment stage is not sent late; live reminders catch up until the next offset / start.
   - Finance and support get `notifications.view` (to answer "I didn't get the SMS"); only academy-admin gets manage.
   - Send log is a menu entry, not a hub section, so finance/support do not get the whole settings hub.
