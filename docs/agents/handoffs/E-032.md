# E-032 — One-click migration from WordPress + competitor landscape

**Agents:** market-researcher (new) → product-manager → tech-lead (orchestrated) · **Date:** 2026-11-06 ·
**Branch:** `feature/migration-wordpress` → PR into `develop` (not merged) · **Stage:** Phase 1 + 2 done; **Phase 3 waits for Farjad**

1. **Task:** research the WordPress LMS stacks Iranian academies use and the competitor field, design a one-click
   WordPress → Edvora migration, then (after approval) build the MVP importer, WP plugin and admin flow.

2. **Output**

     WP → Edvora field map. Sources: 55, schema checked against plugin source.
   - `docs/research/competitors.md`: global SaaS, open source, WordPress and Iranian platforms (Doresaz, Skyroom,

   - `docs/product/wp-migration.md`: PRD with stories W1–W26 (Given/When/Then), Persian microcopy, client questions.
   - `docs/adr/011-wordpress-migration.md`: options compared, decision, interchange format v1, pipeline, collections,
     token security (status *proposed*).
   - `.claude/agents/market-researcher.md` + roster row.

3. **Decisions made (proposed, need Farjad)**
   - **Plugin first, REST fallback.** A thin "Edvora Migrator" plugin reads the DB and emits source-shaped NDJSON. It
     pushes signed chunks or downloads a signed bundle. Mapping lives in TypeScript, so fixes ship without a plugin
     update. REST (application password + Woo keys + LifterLMS key) is the fallback; it misses phones in usermeta and
     theme meta. WXR is for posts and media only. SQL-dump import is deferred.
   - **Stacks for Phase 3:** WooCommerce core (users, phones, products → courses, orders, coupons, Zarinpal/Zibal/IDPay
     refs, Woo Memberships), **LifterLMS** (IBA runs it), **Tutor LMS**. Studiare (the #1 Iranian theme by sales) is
     blocked until we have a sample site. LearnPress comes next. LearnDash is skipped in v1.
   - **No password hashes imported.** Students log in by OTP on phone; staff re-onboard with TOTP (ADR 007). Checking
     phpass/bcrypt in Node works (scheme verified in core `pluggable.php`) but isn't needed.
   - Users are matched by normalised phone (Digits → WP SMS → billing phone …). Duplicates go to review, no silent
     merge. Users without a phone are held, not created. A user who already exists in another academy only gains
     membership. New `users.contactEmail`; a WP email never becomes a login email.
   - **Money:** `toRial()` with IRR ×1, IRT ×10, IRHR ×1,000, IRHT ×10,000, read per order. Fractions and unknown
     currencies are refused.
   - **Idempotent re-runs** via `import-refs` and checksums. Edvora-side edits are never overwritten, and nothing is
     deleted. Dry run is mandatory before the run.
   - **Token:** one-time secret per tenant and job, 72 h expiry, revocable. Requests are HMAC-SHA256 signed with a
     timestamp and nonce. The secret is stored as a hash plus an AES-GCM sealed copy (tech-lead's correction: a hash
     alone can't verify an HMAC).
   - **Redirects:** a tenant-owned `redirects` collection served from a catch-all page (no per-request middleware DB
     hit). It answers 308; search engines treat 308 like 301.
   - Background work uses the Payload jobs queue, the first use in the repo.
